Settings

Models

Classifier Summarizer

Used by the next triage. A different model gives a different cached result.

Code map

Impact scores come from a map of your repos. Index now links the checkouts in the local directory (indexed as they are on disk, including uncommitted changes) and clones the org's other repos, then rebuilds the map; only repos that changed are re-read. A PR from a repo that isn't in the map is added when it's triaged: linked from the local directory, else cloned. Cross-repo impact only counts repos in the map, so index the whole org. The server defaults are PR_MANAGER_CODE_ROOT and PR_MANAGER_ORG.

Summary language

Language of headlines, summaries, review notes and issues. PRs are reviewed in English and translated in the background once the triage ends, so both are kept and the EN button switches between them; a PR triaged in another language is translated when you open it. Translations are cached. Code, paths and quoted evidence stay as they are.

Review budget

MoreLess

How much of the PR goes to human review. Toward Less, a review that found nothing counts for more, and on Less and Least it lets a behavior change (or another unit held at skim) drop to none. Pinned units (force_human paths, critical impact, medium or worse issues, failed reviews) stay in human review at every step. Moving the slider re-buckets the open PR without re-running it.

Review tools

codex and claude-code summarizers only. Slower, but catches claims about code outside the diff. Applies to the next triage.

Incremental review

A unit keeps its review when its own diff is unchanged and so are the units it was judged against: its callers and callees, the other changes in its file, and any unit code moved between. Everything else runs on the whole diff, so the buckets are as fresh as a full run's. A rebase, a different model, a different review setting or a rebuilt code map carries nothing, and neither does re-running a PR with Force.

Static analysis

A tool runs only when the repository has a config for it (.golangci.yml, eslint.config.js, ruff.toml) and it is installed; shellcheck runs on changed shell scripts. The built-in credential scan needs nothing installed and runs whenever this is on. Findings go to the reviewer as facts, raise the unit's likelihood, and show up on the Issues tab, where you can dismiss one. Applies to the next triage.

Fix issues

The cached clone option checks out the PR branch in the app's clone and applies changes there. It stops if that clone already has local changes. Existing fix results keep their current location. The selected issue and code touched by each fix are reviewed after every round.

Uncommitted changes

The checkout has changes that aren't committed. A fix in a separate worktree starts from the last commit, so it wouldn't see them.

Commit and fix commits everything, with a message the summarizer writes, then fixes in a worktree. Fix in current branch applies the fix to your checkout, next to your uncommitted changes.
