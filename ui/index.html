Settings

Models iUsed by the next triage. A different model gives a different cached result. The reviewer triages, summarizes and reviews each unit in one call. Set it to off for a classify-only run, which picks a classifier instead.

Reviewer Classifier Chat agent

Code map iImpact scores come from a map of your repos. Index now links the checkouts in the local directory (as they are on disk, uncommitted changes included), clones the org's other repos, and re-reads only repos that changed. A PR from a repo outside the map is added when it's triaged. Cross-repo impact only counts mapped repos, so index the whole org. Server defaults: PR_MANAGER_CODE_ROOT, PR_MANAGER_ORG.

Summary language iLanguage of headlines, summaries, review notes and issues. PRs are reviewed in English and translated in the background by the translator model; the EN button switches between the two. Translations are cached, so a new translator applies to PRs not translated yet. Code, paths and quoted evidence aren't translated. Defaults are the fastest models in a benchmark: gpt-5.6-luna at minimal effort on codex, Claude Sonnet 5.5 at low on claude-code.

Translator Effort

Review budget iHow much of the PR goes to human review. Toward Less, a clean review counts for more, and on Less and Least a unit held at skim can drop to none. Code drops to none only when its measured impact and likelihood alone score under skim. Tests, docs and fixtures stay in auxiliary unless the review or a weakened test raises them. Pinned units (force_human paths, critical impact, medium or worse issues, failed reviews) always stay in human review. Moving the slider re-buckets the open PR without re-running it.

MoreLess

Walkthrough steps iWhat one step of the walkthrough holds. None: a single declaration. By file: a file's changes in file order; a file over 400 changed lines is split between declarations. By relation: declarations that name each other (caller and callee), a test and the code it is named after, and small changes in one file, up to 8 declarations and 400 changed lines a step. In a step with several changes, each change's review sits above its code, and reviews without issues start collapsed unless the change is in human review. Every step lists the changed definitions it uses from elsewhere, collapsed. Only changes how the walkthrough is shown, so it applies at once. It is separate from the grouping the reviewer model uses to save calls.

Review view iWhat the app opens with. The buttons on the page switch the mode and the diff view until the next reload. With focus on, a walkthrough step of several changes (or showing a whole file), or any file in the Files mode, opens scrolled to its first change in human review instead of its top. A step picked by its numbered dot always opens at its top.

Sidebar iHow many of a repo's latest results the sidebar lists before a Show more button, and how long a change stays listed without being touched: triaged, opened, or changed (reviewed marks, dismissals, drafts, fixes). A change left that long is hidden; its results stay in the cache, so opening its link lists it again, and the line under the list shows the hidden ones. The open result is always listed. 0 lists them all, and keeps every change. A row's ✕ deletes the change and its results from the cache, without asking unless that box is checked. Applies at once.

Chat hotkeys iOpen puts the cursor in the chat agent's prompt, or brings its pop-out window to the front; the default is A, or Ctrl+/ (⌘/ on a Mac) from anywhere. Collapse turns the open chat back into its icon; Esc always does while you are in the chat, and the key set here does from anywhere. Give both the same key to toggle the chat with it. Click a field and press the keys. A key without Ctrl, Alt or ⌘ only works when you aren't typing in a field.

Chat agent actions iThe chat agent can propose actions under its answer: open a unit or tab, draft a pending comment, dismiss or restore an issue, mark units reviewed, fix issues, review units or the whole change again, fetch the GitHub comments again, rewrite the overview or sequence, rebuild the code map, and reply on, resolve or submit a review on GitHub. Each one shows as a card with Run and Skip. Navigation always runs at once. What it posts to GitHub or pushes always waits for your click, whatever this says.

Batch classify iUp to 6 units share one classify call, which is much faster on large PRs, especially with codex and claude-code. Answers lean slightly toward skim on borderline helpers. A unit the answer misses is classified on its own. Applies to the next triage.

Review tools icodex and claude-code reviewers only. Slower, but catches claims about code outside the diff. Applies to the next triage.

Incremental review iA unit keeps its review when its diff is unchanged and so are the units it was judged against (callers, callees, other changes in its file). Everything else is re-reviewed. A rebase, a different model or review setting, a rebuilt code map, or Force carries nothing over.

Static analysis iA linter runs only when the repo has a config for it (.golangci.yml, eslint.config.js, ruff.toml) and it is installed; shellcheck runs on changed shell scripts. The built-in credential scan always runs. Findings go to the reviewer, raise the unit's likelihood, and appear on the Issues tab. Applies to the next triage.

Fix issues iThe cached clone option checks out the PR branch in the app's clone and stops if that clone has local changes. Existing fix results keep their location. The issue and the code each fix touches are reviewed after every round.

Uncommitted changes

The checkout has changes that aren't committed. A fix in a separate worktree starts from the last commit, so it wouldn't see them.

Commit and fix commits everything, with a message the summarizer writes, then fixes in a worktree. Fix in current branch applies the fix to your checkout, next to your uncommitted changes.

Fix a commit or branch

Fix current code leaves the checkout on its branch and fixes the issues in its code as it is now, next to any uncommitted changes. The fixer finds the reviewed code there and skips issues that no longer apply. The result is a review of the current branch.
